# 日本語の文書を書く

AGENTS.md の Writing 節を前提にする。ここにあるのは、文書の長さがあって初めて問題になる規則だけ。

## 書く前に

- 主メッセージを一文で書く。書けなければ素材が足りていないのであって、書き方の問題ではない
- 見出しだけを縦に並べて読み、論旨が通ることを確かめてから本文に入る
- 節ごとに厚みを決めておく。重要な節を厚く、軽い節は短く。全節が同じ厚みになる構成案は、網羅を装っている

## 整形

- 一文ごとに改行する。段落の区切りは空行
- コード、差分、ログ、設定の断片はコードブロック
- 本筋から一段外れる補足は脚注（`[^ラベル]`）に降ろす
- 見出しは節の結論を含む句にする。ただし結論を言い切るセリフにはしない（見出しでオチを知らせない）
- 用語の初出は太字、以後の言及は「」

## 視点

- 行為者を主語にする。「特定され、判明した」ではなく「調査して特定した」
- 読者は「開発者」「読者」と役割で呼ぶ。「あなた」は場面の導入（「〜としよう」）と結びに限る
- 対象を指す語は具体的に。「AI」「ツール」のような広い語でぼかさない

## 段落と論証

- 一段落に一トピック。先頭文だけで何の話かわかる
- 段落の頭で、前の段落との関係を接続語で示す（「であれば」「実際」「しかし」）
- 新しい概念は、先に対象を置き、次に働きを述べ、必要なら三文目で定義する。「XはYである」から始めない
- 論証は一方向に進める。結論を出してから反論を処理して言い直す構成にしない
- 因果を主張するときは、なぜそうなるのかを一文で示す。「AだとBになる」だけで終えない
- 異なるものを「同じ」とまとめない。別々の決定、別々の原因は腑分けして書く
- 検出・保証・解決を「必ず」できるかのように書かない。「〜しやすい」「〜が成り立つときに限り」
- 否定するときは、否定する命題そのものを「」で書き出す。「何もかもが解決するわけではない」で済ませない
- 譲歩（「ただし」「とはいえ」）を置いたら、そのあとで論を進める。逆接で終えない

## 事実と意見

- 事実には出典、意見には「筆者は」。文末の形では区別できないので、話者標識を立てる
- 出典を示せない事実は、事実として書かない

## 結び

- 要約の繰り返しではなく再統合。「以上、〜について解説した」を書かない
- 調査レポートは事実で終えず、次に何をすべきかへ最低一段落つなぐ。ただし根拠が支える範囲を超えた処方は書かない

## 書いたあと

見出しと各段落の先頭文だけを抜き出して読み、次の5点を確かめる。

1. 骨組みだけで論旨が通るか
2. 見出しがラベルでなく結論になっているか
3. 同じ書き出しの型が3回続いていないか
4. 節ごとに濃淡があるか
5. 結びが再統合になっているか（レポートなら So What に着地しているか）

判定できなければ、文書はまだ骨組みの水準で崩れている。本文を直す前に骨組みを直す。
